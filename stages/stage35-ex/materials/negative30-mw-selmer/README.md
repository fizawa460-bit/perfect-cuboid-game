- 14証拠ZIPの全172ファイルを、元のチェックサムに対して検査した。著者パッケージ13件と、row372の独立監査パッケージ1件。元ZIPのSHA256、全メンバー対応、本文・監査の出典は [SOURCE-INVENTORY.json](SOURCE-INVENTORY.json)。

- row370/373/374/375の証明本文は、第1群で保存した同一バイトの親本文を参照する。各ZIPは当時のスナップショットとして保存し、同一内容のGit blobは共有できる。
- 大きいJSON・表・群演算テープは決定的gzipで保存した。下記の再現器が元の名前に復元し、元SHA256SUMSを全件照合してから、一時領域で元コードを実行する。圧縮は数学内容を変えない。
- **row377の監査本文は取得できていない。** 指定のGoogle DocはBOMのみを返した。台帳の報告済み監査表示は出典付きで残すが、読み取れない報告書を確認済みと扱わない。読める原監査本文は13件。
- row372は当時の監査が著者専用ZIPを取得できなかった限定を保持する。今回収載したものは独立監査の再構成コード。row371/375/381の当時の群演算チェーン監査の留保も原報告のまま残す。後続row382の別実装テープは別証拠として収載し、古い判定を書き換えない。
- 元READMEのPENDINGやNEXTは当時の記録。現在の研究再開指示ではない。新しい独立数学監査や正式採択は付与していない。

## 再現

保存整合性は標準Pythonのみで検査できる。

```bash
python verify_migration.py
python -O verify_migration.py
```

算術の再実行はPython 3.12、SymPy 1.14.0、python-flint 0.9.0で行う。元コードはassertを用いるため、算術の実行には-Oを付けない。

```bash
python -m pip install -r requirements.txt
python replay.py --output /tmp/stage35ex-materials02-replay.json
```

既に終えた選択ジョブは同じ凍結入力に対して再利用できる。重い全チェーン検算を含める場合は [REPLAY-JOBS.json](REPLAY-JOBS.json) のIDを指定するか、明示的に全件を選ぶ。

```bash
python replay.py --resume --output /tmp/stage35ex-materials02-replay.json
python replay.py --job 375-verify_row375 --output /tmp/stage35ex-row375-replay.json
python replay.py --all --output /tmp/stage35ex-materials02-all.json
```

row382のC++群演算テープ検算や元パッケージの直接利用には、新しい出力ディレクトリを指定して完全復元できる。

```bash
python restore_package.py --row 382 --destination /tmp/stage35ex-row382-original
```

復元後は元READMEのC++17手順を使う。尾部素数表の完全再計数は元検証器の `--recount-tail` で選択できる。今回実際に実行した範囲・終了値・比較方法は [LOCAL-REPLAY.json](LOCAL-REPLAY.json) に記録する。未実行のジョブをPASSとは表示しない。
