# Stage32 CUT-CERT-LIFT startup

This is an on-demand independent research lane. It is intentionally **not** a new canonical ordinary command yet.

Operator command: `stage32certlift-mainbatch`.

## Purpose

Use hostile-audited CUT193..CUT198 closure evidence as the initial source-locked dataset and search for a symbolic, parameterized obstruction explaining a large fraction of the repeated finite-ring/Picard64 infeasibility.

The target is not merely another bounded wave. The target is an exact implication of the form

```text
H(d,e,prefix invariants, Picard/HNF signature) => exact completion infeasibility.
```

A useful result must be solver-timeout independent and must carry an exact population adapter before any scope enlargement.

## Concurrency contract

This lane may run while CUT199 or EX5 BC2-36 heavy flows are active because it:

- starts from hostile-audited historical evidence and does not require their unfinished outputs;
- does not mutate CUT/EX5/178/MB state;
- does not grant itself MAIN credit.

Heavy compute is **allowed**, not mandatory and not automatically armed. Use light/retained evidence first when it already answers the active question. When fresh computation has clear information gain, CERT-LIFT may create its own bounded heavy experiment.

Any such heavy experiment must:

- have a dedicated runkey with fresh commit-range authorization;
- preflight projected peak Actions artifact storage against the repository 500 MB budget;
- prefer runner-local raw computation and persisted compact deterministic certificates;
- use bounded waves and explicit retention when raw artifacts are unavoidable;
- classify workflow lifecycle explicitly (`MANUAL` by default; `ACTIVE_AUTO` only when justified and allowlisted);
- stop on storage uncertainty, accidental authorization, or unresolved UNKNOWN/resource walls;
- remain semantically distinct from simply rerunning the active CUT wave.

Heavy execution may be used for targeted counterexample search, invariant discrimination, symbolic-certificate discovery, or cross-wave/cross-e challenge. It is not prohibited merely because another Stage32 heavy workflow is running.

## Certificate semantics

Do **not** infer a symbolic law from timeout-sensitive execution-route labels. CUT193 already records that independent fresh replay may classify the same closed set by a slightly different modular/HNF route while reproducing the exact closure set. CERT-LIFT therefore treats the exact audited closure and the deterministic replay witness as authority; runtime route labels are diagnostic only.

For every candidate rule:

1. derive it from exact retained certificate data and/or a separately source-locked targeted experiment;
2. test it against all available audited nonclosed/residual controls;
3. record false positives explicitly;
4. only after a zero-false-positive exact implication exists, attempt symbolic proof;
5. only after symbolic proof, challenge a different wave and then the e10 scout through an exact adapter.
