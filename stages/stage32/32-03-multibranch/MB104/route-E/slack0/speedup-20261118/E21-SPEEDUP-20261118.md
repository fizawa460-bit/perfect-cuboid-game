# E21 speed-up — tools for degrees 6–7 (research note, 2026-11-18)

Status: research code + measurements, **numerical, not audited, zero credit**. STATE is not changed. No new
mathematical claim; only the cost of the E21 computation (`../numeric-upto5-20261118/`) is changed.
Code: this folder (`speedup-20261118/`). Run from a data folder (`data4/`, `data5/`, …) as shown in §6.

## 2. Braid-orbit census (`braid_orbits.c`, `census.py`, `hurwitz_char.py`)
- Nielsen tuples (g_y) of involutions, g_y with t(y) transpositions, product 1, transitive, up to conjugation.
  Random tuples of the profile are generated and each orbit met is explored completely (full braid group B6 by
  Hurwitz moves; inside the profile, pure braid group by the generators A_ij). The census is complete when the
  orbit weights add up to the exact Hurwitz number, which happens in every profile for n = 5, 6, 7.
- **n = 6** (27 profile representatives): split profiles only
  (0,2,2,2,2,2) = 432 (A6) + 96 (order 60) + 5 × 6 (order 24); (1,1,2,2,2,2), (1,2,1,2,2,2) = 2,520 (S6) + 18 (order 48);
  the four (0,1,2,2,2,3)-type and (0,3,1,2,2,2) = 60 (S6) + 6 (order 48); (1,1,1,1,3,3) = 16 + 16. The small orbits are the
  decomposable covers. All other profiles are one orbit.
- **n = 7** (21 representatives, 118,568 weighted covers): **20 profiles are a single pure-braid orbit** (one seed
  suffices). Only (2,2,2,2,2,2) splits: 45,360 + 19,600 (both A7) + 1,680 (PSL(3,2)); it holds 56 % of all
  representative covers. So degree 7 needs 1 seed per profile and 3 seeds for (2,2,2,2,2,2).
- Use: the stopping rule per orbit is exact, and "covers that the branch-point moves never reach" are identified
  in advance instead of being searched for.

## 3. Covers (`mono.py`, `seed.py`, `monodromy.py`)
- Same square system as `covers.py` (P, Q, critical points; three critical points fixed). All known covers of a
  profile are tracked **together** (one stacked linear solve per step, RK4 predictor, 3 Newton correctors) while
  the five finite branch points move along a random triangle B → B1 → B2 → B. New covers are closed under Stab(t)
  × complex conjugation.
- Identity of covers: `monodromy.py` follows the n roots of P − wQ around fixed loops around the five finite
  branch points (batched companion eigenvalues, a step is halved only for the covers whose root matching is
  ambiguous) and returns the tuple, checked to be a valid slack-0 tuple of the profile and brought to canonical
  form. Exact, no tolerance, and it also gives |Aut| exactly. All 2,636 endpoints at n = 6 gave valid tuples.
- `covers.analyse` rejects genuine covers whose odd point lies near a critical point of another fibre (test
  |f′| < 1e-6); n = 5 profile (1,1,1,2,1,2) had one such cover (two critical points 3.6e-4 apart), which is why the
  E21 random search stalled at 239 / 240. `analyse_loose` relaxes only that test (1e-10); the point-separation
  test stays at 1e-6 (relaxing it admits near-degenerate spurious solutions).
- Seeds (`seed.seq_seed`): start from a random map of degree n (2n − 2 simple critical values), send one critical
  value at a time to its point of B; at each step all free critical points are tried in parallel and a surviving
  path is kept. Random-start Newton at n = 7 converged 824 / 2,000 times, all to degenerate solutions.

## 4. Pair search (`search2.py`, `cost.py`)
- Unordered 4-subsets keyed by (sorted labels, j-invariant on the sphere); the ordering is resolved only on a hit.
- Split subsets: with j ≥ j_min, any F_a points of f and F_b points of q contain ≥ 4 matched pairs in both as soon as
  F_a + F_b ≥ n_A + n_B − j_min + 4. The table holds only the first F_b points of each table cover.
- Verification (Möbius map, all distances, dedupe of (q, M)) is batched in numpy; the 40-digit path for ambiguous
  cases is unchanged.
- Predicted table size + lookups (`cost.py`):

| pair | E21 layout | new | factor |
|---|---|---|---|
| (5,6) | 4.8·10⁷ | 4.3·10⁶ | 11 |
| (6,6) | 7.8·10⁸ | 1.8·10⁷ | 44 |
| (6,7) | 1.6·10¹⁰ | 7.3·10⁷ | 216 |
| (7,7) | 1.6·10¹⁰ | 3.9·10⁸ | 41 |

  The (7,7) table (1.1·10⁸ entries) fits in memory; nothing has to be streamed.
- Same data, same machine: (4,4) hits |Ω| ≤ 4: 763 in both codes (all non-birational); (4,5) none; (5,5) 2,530 hits,
  all non-birational. (The counts of distinct (f, q, M) differ slightly from the E21 table because the cover lists
  were recomputed; the conclusion is the same.)
- Caveat seen at (5,5) with the recomputed list: 40-digit accepted ≤ 7.5·10⁻²², rejected ≥ 1.4·10⁻¹⁸, a gap of only
  3.5 orders (E21: 20 orders). The recomputed degree-5 list contains covers with nearly colliding points whose
  40-digit refinement is less accurate; for degrees 6–7 these need more digits (e.g. 60) before a classification.

## 5. Remaining costs for degree 7 (estimates)
- Covers: ≈ 0.56 s per cover at n = 7 (measured on 672), so the 118,568 representatives take ≈ 18 core-hours
  (≈ 5 h on 4 cores). Half of it is the monodromy labelling in Python; tracking in C or Newton root following would
  cut it further.
- 40-digit refinement (mpmath, `hp.refine`) is now the slowest step: ≈ 1 s per degree-6 cover. For 118,568
  covers a faster multiprecision library (python-flint/arb) or refinement only of the covers that occur in
  ambiguous cases is needed.
- Pairs: (6,7) and (7,7) about 7·10⁷ and 4·10⁸ table operations plus verification; hours, not days.
- Not done: the seeds for the two small orbits of (2,2,2,2,2,2) at n = 7 (seq_seed reaches a random orbit; the
  tuple tells which one, so one repeats until all three are hit).
