# fastmono — directed monodromy for the degree-7 profile 2,2,2,2,2,2 (research note, 2026-11-19)

Status: research code + measurements, **numerical, not audited, zero credit**. STATE is not changed. No new
mathematical claim. Builds on `../speedup-20261118/` (mono.py, PR #1881) and `../fast40-20261118/` (PR #1885). All runs
were done in a scratch container; the running degree-7 computation was not touched.

## 1. Summary

The cover list of the largest degree-7 profile, 2,2,2,2,2,2 (66,640 covers, weighted = unweighted), was computed
**from one seed per braid orbit in about 15 minutes on one core** (`mono_dir.py`). With the original approach
(`speedup/mono.py`: track every known cover around a random loop, then add symmetry images) one loop takes hours.

| run (same machine, one core each, 2-3 jobs in parallel) | after | covers |
|---|---|---|
| mono.py behaviour (`mono_rep.py --all`) | 253 s / 25 min | 1,677 / loop 2 still running |
| one representative per symmetry orbit (`mono_rep.py`) | 25 min | 21,027, then stuck (images rejected by `analyse`, §4) |
| directed (`mono_dir.py`) | 12.7 min | 66,609 |
| directed + robust image polish (end pass from the checkpoint) | +2 min | **66,640 = Hurwitz number** |
| final code, from scratch, another random seed (`--seed 7`, 6 seed tries) | 15.8 min | **66,640** |

Checks (§3): the predicted class was right for every tracked move (2,159/2,159) and every sampled image (1,885/1,885).
Re-numbering all 66,640 covers numerically: 65,606 agree with their assigned class, **0 disagree**, 1,034 cannot be
numbered in double precision (almost-coincident critical points, §4).

## 2. What changed

1. **Faster numbering** (`fasttuples.py`). `monodromy.tuples` samples each loop with 60 points per radial segment; the
   step routine already subdivides whenever nearest-root matching is ambiguous, so 12 points give the same permutations:
   2,000/2,000 identical tuples, 42 → 9.6 ms per cover.
2. **Predict, then track** (`braid.py`, `mono_dir.py`). A half-twist of two branch points with equal profile entry is a
   fixed braid; with monodromy.py's base point W0 = −0.663−0.421i and loops it acts on tuples by an explicit formula.
   Six moves (pairs {i,−1}, {−i,1}, {1,i}, both directions) were identified on 40–60 covers each (`probe.py`,
   `probe2.py`, 100 % agreement). Before tracking, the target class of every (cover, move) is computed; only covers whose
   target is still missing are tracked. Each successful track gives a new cover (≈ 25 new covers per track with images).
3. **Symmetry images named without root following** (`autact.py`, `learn_aut.py`). Each of the 48 elements of
   Stab(prof) in Aut(B)×⟨conj⟩ acts on tuples as t'[π(y)] = h·(e_y t[y] e_y⁻¹)·h⁻¹ with short words e_y (≤ 2 letters);
   the words were learned on 12 covers and checked on 30 per symmetry (all agree). Images then get their class from
   the rule; a random 3 % is still numbered numerically as a check.
4. **Robust image polish** (`mono_dir.make_to_u`). mono.py's `to_u` sends three critical points to fixed positions and
   runs Newton. If two critical points almost coincide the Jacobian has condition 10¹⁴–10¹⁹ and Newton spoils an exact
   Möbius image. Now all choices of the three points inside their branch-point groups are tried, Newton is skipped when
   the transform already solves the system, and the best iterate is kept. This closed the last 31 covers.
5. **Seeds**: when no prediction leads to a missing class, the code asks for another seed (`seed.seq_seed`) and keeps
   it if it is new. 2,2,2,2,2,2 needed 4 seeds (orbits 1,680 / 19,600 / 45,360). Note: every entry of the tuple is a
   double transposition, so all three orbits have even monodromy; the group order only separates PSL(3,2) (168).

## 3. Checks

- moves: predicted class = numbered class for 2,159/2,159 tracked covers whose endpoint could be numbered.
- images: 1,885/1,885 random images agree (31 sampled images could not be numbered in double precision).
- `verify_all.py` (all 66,640, independent of the run): 65,606 agree, 0 numbered to another valid class,
  1,008 root following fails, 26 give an invalid tuple. `badcheck.py`: the 26 stay invalid at 30, 60 and 120 points per
  segment; all 26 fail `analyse` and have critical points 3·10⁻⁶ – 2·10⁻⁴ apart.
- the from-scratch run (`--seed 7`): 65,287 agree, 0 numbered to another valid class, 853 root following fails, 500
  invalid tuples, all of them images, median critical-point gap 3.7·10⁻⁵ (`badcheck2.py`).
- `learn_aut.py` rerun on another sample of the finished list gives the same 48 rules (30/30 each).
- every cover is in a different class by construction (exact canonical tuples), the weighted count is 66,640.0.
- `orbitcover.py`: the 66,640 covers form 3,020 Aut(B) orbits (24 elements, no conjugation); every orbit has a member
  that passes `analyse` in double precision.

## 4. Covers with almost-coincident critical points

2,221 of the 66,640 covers fail `analyse` in double precision (two critical points over *different* branch points are
3·10⁻⁶ – 10⁻³ apart, a near-common factor of P and Q). They are exact Möbius images of covers that pass, which is how
they were found. mono.py drops such covers (that is why the representative-only run got stuck at 21,027).
`export.py` therefore writes `cov_7_222222.pkl` / `rej_7_222222.pkl` (mono.py format) with the 64,419 covers that pass
`analyse`; `fast40/build_all.py` refines those at 40 digits and regenerates all Aut(B) images itself. The complete list
with tuples is `full_7_222222.pkl`.

Test: `build_all.py 7` on that cov file refined the 64,419 covers (worst residual 1.1·10⁻²⁸, 862 core-s) and produced
66,664 entries. Its invariant de-duplication (tolerance 10⁻⁷) left 24 duplicates; `exact_dedupe.py` names every entry by
the representative's tuple and the symmetry rule: exactly the 66,640 classes of the run, plus the 24 duplicates, which
it removes (`all_7_exact.pkl`). 1,034 covers cannot be numbered in double precision; their class rests on the
symmetry rules (§2.3), and a 40-digit numbering would confirm them.

## 5. Usage

```
python3 learn_aut.py <checkpoint with a few hundred covers> 2,2,2,2,2,2 30   # writes aut_rules_7_222222.pkl (done)
python3 mono_dir.py 7 2,2,2,2,2,2 --rules aut_rules_7_222222.pkl [--maxtime s] [--seed S]
python3 export.py ckpt_dir_7_222222.pkl 7 2,2,2,2,2,2                       # (mono_dir does this at the end)
python3 verify_all.py ckpt_dir_7_222222.pkl k 3                               # independent re-numbering, chunk k
python3 ../fast40-20261118/build_all.py 7 1                                    # in the folder with cov_/rej_ files
python3 exact_dedupe.py all_7.pkl full_7_222222.pkl aut_rules_7_222222.pkl     # exact de-duplication
```
A checkpoint is written after every round; rerunning the same command resumes.

Limits: the moves and symmetry rules depend only on the geometry (base point and loops), but they were identified on
2,2,2,2,2,2, where every entry is an involution, so g and g⁻¹ cannot be told apart. For other profiles rerun `probe.py`
/ `probe2.py` and `learn_aut.py` first (the code checks predictions and would show mismatches).

## 6. The other degree-7 profiles that stalled (added 2026-11-19)

At the request of the production run, the seven degree-7 profiles whose lists stalled a few covers short (same cause:
almost-coincident critical points) were computed with the same code.

|---|---|---|---|---|
| 0,3,1,3,2,3 | 168 / 168 | 22 s | 168 / 0 / 0 | 0 |
| 1,2,1,2,3,3 | 3,080 / 3,080 | ≈ 9 min + 1 min end pass | 3,054 / 0 / 26 | 36 |
| 1,1,2,3,2,3 | 3,080 / 3,080 | ≈ 11 min + end passes | 3,034 / 0 / 46 | 51 |

| 1,2,1,3,3,2 | 3,080 / 3,080 | ≈ 35 min (trivial stabiliser) | 3,055 / 0 / 25 | 32 |
| 1,2,2,2,2,3 | 14,448 / 14,448 | ≈ 50 min | 14,302 / 0 / 146 | 194 |

What had to be added:
- **Full twists** (`braid.path_full`): a half-twist changes the profile when the two points carry different entries (or
  a fixed critical point); the full twist is a pure braid, and its action is the half-twist formula applied twice
  (`probe_full.py`, 6/6 moves agree on 38-40 covers).
- **Loops of the point 0 around 1 and i** (`braid.path_loop`, `LOOPS` in mono_dir, learned by `probe3.py`, 40/40 each).
  Without them the profiles with trivial stabiliser left 4 classes unreachable.
- **Symmetry rules by key**: the rules are geometric, so the ones learned on 2,2,2,2,2,2 are looked up by (conj, π)
  for every profile (sampled images agree on every profile).
- **40-digit tracking** (`hp_track.py`, python-flint): when a predicted move fails in double precision (critical points
  collide on the way), it is tracked at 40 digits (about 1 s per move; tolerance 10^(−0.6·dps)). Endpoints whose
  numbering fails in double precision get the predicted class and `confirmed = False`.
- `export.py` also writes `extra_<n>_<prof>.pkl`: the covers that fail `analyse` are not brought back by build_all's
  Aut(B) images when the stabiliser is small, so they are handed over separately (u vector, ys, tuples, flags).
