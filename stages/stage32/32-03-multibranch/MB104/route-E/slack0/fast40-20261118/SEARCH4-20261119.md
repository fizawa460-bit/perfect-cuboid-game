# search4 — a faster pair search for degree 7 (research note, 2026-11-19)

Status: research code + measurements, **numerical, not audited, zero credit**. STATE is not changed. No new
mathematical claim. Builds on `search3.py` (PR #1885). Measured on degree-7 cover lists recomputed in a scratch
folder; the running degree-7 computation was not touched.

low); search4 ≈ 7–10 GB once for all 4 workers, mostly the transient unpickling of `all_7.pkl`.

## 2. Where the time went

With the 22,848-cover table, about 3.5 M candidates passed search3's cross-ratio window. Shrinking the window by
three orders (§3 (5)) removed almost none of them: 90 % are **exact** coincidences of four odd points of two
different covers (cross-ratio difference ~ 10⁻¹⁶, labels mostly all "e"), followed by no fifth match. They are not
caused by the window and their number grows with the table. The second cost, at the larger table, was the 40-digit
check of "ambiguous" candidates: 0.5 M of them at 78,888, nearly all of the type "the Möbius map squeezes many query
points next to one table point", so that ≥ 16 query points are within 10⁻⁴ of *some* table point but of only a few
distinct ones.

## 3. Changes (details in the header of `search4.py`)

- (4) key points = the 40-digit points rounded to double.
- (5) cross-ratio window from an error estimate, TOL · (S_X + S_Y) · (distance to the nearest pole), never larger
  than search3's; the largest measured (difference / window) over all true matched quadruples is 1.6·10⁻⁵.
- (6) `verify_nb.prefilter` (numba): the label, cross-ratio, Möbius and "≥ 16 close points" tests of search3 for each
  candidate, with early exit after 3 unmatched points. Same tests, same thresholds.
- (7) one-to-one bound: nclose ≤ number of distinct table points with a close image (a hit's matching is
  one-to-one). Removes the squeezed candidates before the 40-digit step (40-digit checks on 1/16 of the 6-profile
  test: 62,308 → 592).
- (8) self part: window (5), compiled pre-filter, index maps computed once per q.
- (9) memory: one copy of the pickle for a = b, chunked table build, the `all` list dropped and table covers rebuilt
  from (representative, Aut(B) index) on demand (checked on 200 random covers at every start), `JOBS=k` fork after
  the table build.

What decides a hit is unchanged: the candidates that reach the numpy / 40-digit code of search3 are a subset that
contains every candidate search3 could record with |Ω| ≤ 4 (rules (6)–(7) only drop candidates whose |Ω| lower bound
is > 4 under search3's own "a true match is within 10⁻⁴ in double" assumption). The window (5) is the only change
that rests on an error estimate; its margin is printed on every run (`true_quad_win_ratio_max`).

## 4. (6,7)

Both codes find no |Ω| ≤ 4 pair on 2,520 degree-6 covers (profile 112222) × the 78,888 degree-7 table covers. This is
the expected answer (degrees 6 and 7 are coprime, FAST40 §4), so it checks only that the a ≠ b path runs and is
faster; the hit-for-hit comparison of a ≠ b with hits present was not possible on these lists. The a ≠ b path uses
the same code as the main part of a = b, which was compared hit for hit above.

## 5. A precision warning (also in search3)

On the 6-profile test the 40-digit distances of the ambiguous cases had accepted ≤ 3.0·10⁻²¹ and rejected ≥ 1.06·10⁻²⁰
around the threshold 10⁻²⁰, in search3 and search4 alike (a gap of a factor 3.5, not orders of magnitude). These
come from covers with nearly colliding points. For the main run the 60-digit points (`DPS=60 python3 build_all.py 7`,
FAST40 §2) are recommended, or a look at the cases near 10⁻²⁰.

## 6. Usage
```
pip install python-flint mpmath gmpy2 numba
python3 ../fast40-20261118/build_all.py 7 4                         # all_7.pkl, as before
JOBS=4 python3 ../fast40-20261118/search4.py 7 7 2.5e-6 - 0 1         # 4 workers, one table; res4_7_7_{w}of4.pkl
JOBS=4 python3 ../fast40-20261118/search4.py 6 7 2.5e-6 - 0 1 dir6 dir7
python3 ../fast40-20261118/cmp_hits.py res3_….pkl res4_7_7_0of4.pkl,res4_7_7_1of4.pkl,…   # compare with search3
```
Options (environment): `TOL` (1e-9), `TIERS` (0,1000,inf), `OLDWIN=1` (search3 windows, no compiled filter),
`NB=0`, `ONE2ONE=0`, `HPKEY=0`, `DIAG=1`.
