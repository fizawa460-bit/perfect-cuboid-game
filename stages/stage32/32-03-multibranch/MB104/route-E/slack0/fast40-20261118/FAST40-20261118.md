# fast40 — faster finishing steps for degree 7 (research note, 2026-11-18/19)

Status: research code + measurements, **numerical, not audited, zero credit**. STATE is not changed. No new
mathematical claim. Builds on E22 (`../degree6-20261118/`, PR #1882) and the E21 speed-up tools (`../speedup-20261118/`,
PR #1881). Everything was measured on cover lists recomputed in a scratch folder (degree 4 and 5 complete, degree 6
one profile, degree 7 four profiles); the running degree-7 computation was not touched.

## 2. What was slow, and what changed

- **40-digit refinement.** Same square system and output format as `hp.refine`; Newton at 136 bits with acb matrices,
  stopped when the step is < 10^(−0.75·dps) (quadratic convergence), residual reported after the last step. `dps=60` is
  one argument (`DPS=60 python3 build_all.py 7`): worst residual of the four degree-7 profiles 2.2·10⁻²⁶ at 40 digits,
  3.0·10⁻⁴⁶ at 60 digits.
- **Cover list** (`build_all.py`): reads `cov_n_*.pkl` of `speedup/mono.py` and takes the critical points from its
  `rej_n_*.pkl` (the Wronskian route of `allcovers.load_reps` mis-assigns critical points of covers with nearly colliding
  points and stops with an AssertionError on profile (1,1,1,3,3,3)). Output `all_n.pkl` with `reps`, `all` and `src`
  (representative and Aut(B) index of every table entry).
- **Pair search** (`search3.py`, details in its header):
  1. *Self pairs.* For a table cover q = U∘f of the query cover f itself, search2 meets every quadruple of f again
     (M = id and the Klein-four reorderings): this produced ≈ 3·10⁸ candidates at E22 (6,6). They are now done once
     per f (all Möbius maps between 4-subsets of f's own points, then relabelled for the 24 images).
  2. *Key.* The j-invariant key of search2 has a double pole at cross-ratio 0, 1, ∞: at (5,5) more than 99 % of the
     key matches were quadruples near that pole (one f: 868,197 of 870,225), and at (7,7) this exhausts memory.
     Now: cross-ratio key on the table side, the 6 cross-ratios of each query 4-subset, a relative window near
     0, 1, ∞ (true quadruples: relative error ≤ 4.4·10⁻⁸ measured, window 10⁻⁵), and a 2-d grid instead of a slab.
  3. *40-digit distances* with flint at 200 bits, only where the double distance is < 10⁻⁴, and the 40-digit Möbius map
     from the three best separated nearest-neighbour pairs.
- Hits are compared as sets of (f, q, |Ω|, M up to scale) by `cmp_hits.py`. On every test the old hits are a subset
  of the new ones.

## 3. Precision bug in the E21 / PR #1881 search code

`numeric-upto5-20261118/search.py` (E21) and `speedup-20261118/search2.py` (PR #1881) load `all_n.pkl` before setting
`mp.mp.dps = 40`. mpmath rounds unpickled numbers to the current precision (15 digits), so the stored "40-digit"
points were used at double precision in the ambiguous-case check (threshold 10⁻²⁰): a true match then sits at
≈ 10⁻¹⁷ and is rejected. With the precision set first (search3), (5,5) gains **7 hits** that the old code lost
(all |Ω| = 0, all composites); (4,4) is unchanged (761) and (4,5) has no hit. The 40-digit gap at (5,5) becomes
"accepted ≤ 1.5·10⁻³⁰, rejected ≥ 8·10⁻¹⁵". The E21 conclusion (no birational pair for max(a,b) ≤ 5) is not
contradicted on these lists, but E21's own runs used the affected code; a rerun of E21 with search3 on its own lists
would close this. `degree6-20261118/search2.py` (E22) stores the points as strings (`hp_6.pkl`) and is not affected.
The 777 extra (6,6) hits relative to the E22 code are all |Ω| = 0 composites confirmed at 40 digits; why the E22 code
missed them was not investigated.

## 4. The 40-digit birationality recheck (E22 §3 kept)

`bircheck40.check` is the procedure of `birhp.py` as a function: refine f and the representative r of q (q = U∘r) at
40 digits, rebuild M from three well separated matched odd points, compare all labelled points of f⁻¹(B), and run the
fibre test at 40 digits (fibre of f by mpmath polyroots, values of r∘M; U is a bijection so it drops out). Verdict
"composite" if every fibre has another point with the same value (< 10⁻²⁵), "BIRATIONAL" if some fibre has none
(next distance > 10⁻¹²), otherwise "unclear". search3 calls it on every double-precision BIRATIONAL flag and counts
the 40-digit verdict. Checks: (4,4) all 761 hits → composite (largest second fibre distance 2.6·10⁻³⁷); 20 unrelated
(f, r, random M) → birational (smallest second fibre distance 2.2·10⁻²); the flags of §1 (31 at (6,6), 15 at (7,7)) →
composite, 26/26 or 30/30 points matched. The 12 flags of E22 itself could not be rerun here because the E22 pickles
are not in the repository.

Remark for degree 7: n = 7 is prime, so (f, q∘M) can only be non-birational when q∘M = V∘f, i.e. when q is in the
Aut(B)-orbit of f's cover class; at (6,7) every |Ω| ≤ 4 hit would be birational (no common factor of degrees 6 and 7).

## 5. Cost for the full degree 7 (estimate)

From the two degree-7 samples (672 × 8,064: 58 s; 2,296 × 26,880: 291 s) a model "per query cover a + b·(table size)"
gives a ≈ 0.07 s, b ≈ 2·10⁻⁶ s. For 118,568 representatives against ≈ 0.86·10⁶ table covers this is ≈ 2 s per query,
**≈ 60 core-hours for (7,7)** (upper estimate: the table-dependent part was measured on only two sizes); (6,7) is about a
quarter of that. It shards over query covers (`search3.py a b EPS - k K`); memory for the full table ≈ 5 GB per process.
`EPS = 2.5e-7` gave the same 9,208 (7,7) hits in 189 s instead of 265 s.

## 6. Reproduction (from a data folder with `cov_7_*.pkl` and `rej_7_*.pkl` of `speedup/mono.py`)
```
python3 ../fast40-20261118/build_all.py 7 4          # all_7.pkl (DPS=60 for 60-digit points)
python3 ../fast40-20261118/search3.py 7 7 2.5e-6 k K  # shard k of K; res3_7_7_kofK.pkl
python3 ../fast40-20261118/search3.py 6 7 2.5e-6 - k K dir6 dir7
python3 ../fast40-20261118/bench_refine.py cov_7_111333.pkl    # flint vs mpmath refinement
python3 ../fast40-20261118/cmp_hits.py res2_….pkl res3_….pkl   # compare hit sets
python3 ../fast40-20261118/test_bircheck.py res3_4_4_0of1.pkl 4 4
```
Requires `pip install python-flint mpmath gmpy2`.
