## Final target

Stage32EX5 is not another O210/Q602 attack and is not itself a Stage32 closure theorem. Its job is to rebuild the Stage29 -> Stage32 receiver picture, search materially distinct attack families, and decide whether the frozen breadth package contains a **qualified independent Stage32 route**.

The terminal route-decision outcomes are:

- `QUALIFIED_INDEPENDENT_STAGE32_ROUTE_ESTABLISHED`: at least one route has an exact receiver/population adapter, exact source inputs, explicit proof obligations, and a retained nontrivial mathematical effect on the declared receiver population.
- `FROZEN_BREADTH_PACKAGE_EXHAUSTED_WITHOUT_QUALIFIED_ROUTE`: every candidate in the explicitly frozen EX5 breadth package is classified under the same qualification contract, with typed blockers and minimal re-entry data.

`EX5_ROUTE_DECISION_CLOSURE` closes only this route-selection problem. It is not `FULL_TARGET_CLOSURE`, Stage32 closure, FULL178 completion, or a Perfect Cuboid result.

## Route qualification contract

A route is `QUALIFIED` only when all eight items are explicit and replayable:

1. **receiver target** — exact Stage32 receiver subset/population attacked;
2. **population adapter** — exact identification from frozen Stage29/Stage32 authority, including genus/branch/mask/model/field/quantifier semantics;
3. **new input** — theorem, exact computation, geometric structure, or imported weapon with exact source locator and authority status;
4. **forward implication** — precise `new input -> receiver restriction/exclusion/reduction`;
5. **reverse-scope firewall** — exact statement of what is not implied outside the declared receiver target;
6. **falsifiable execution unit** — bounded proof/computation that actually tests the route;
7. **retained nontrivial effect** — exact new restriction, exclusion, reduction, or population-preserving bridge;
8. **replay path** — compact artifact/verifier or source-complete proof note sufficient for hostile audit.

Failure of item 7 leaves the route intermediate (`PROMISING`, `BLOCKED`, or equivalent); it is not a terminal qualified route.

## EX5-local mathematical invariants

EX5 must preserve these local semantics:

- Receiver scope is explicit; a result on one receiver subset is not silently widened to all Stage32 receivers.
- Numerical class elimination, effectivity, actual curve existence, and endpoint/rational-point consequences are distinct layers.
- A score, heuristic, theorem name, sample hit, bounded diagnostic, or missing-adapter diagnosis is not by itself a qualified route.
- Imported results require an exact object/model/field/population adapter before they can contribute to an EX5 route.
- Bounded package exhaustion means exhaustion of the frozen EX5 package only, not exhaustion of all mathematics.
- A local EX5 result does not self-promote to Stage32 MAIN. Promotion/credit authority remains outside this document.

## Batch semantics

`stage32ex5-mainbatch` advances one coherent EX5 mathematical or route-qualification unit selected by the current authority chain. A failed route is a typed local failure, not automatic EX5 package exhaustion.

If a new breadth cycle is needed, freeze a new explicit package/version rather than silently changing the quantifier of an earlier terminal certificate.

Heavy execution is controlled by the parent repository policy and any stricter gate recorded in current EX5 state; this charter never authorizes it.
