## Vault rule

A dormant item must **not** be reactivated merely because:

- it is finite;
- a CAS could in principle compute it;
- an external AI suggests revisiting the topic;
- the historical parent route is AMBER;
- a nearby theorem exists but does not consume the parked output.

Reactivation requires the recorded downstream dependency to become real. When that happens:

```text
trigger fires
  -> move receiver out of dormant vault
  -> attach exact consuming theorem/kernel
  -> reclassify leaf as Class 1 / 2 / 3
  -> execute or schedule only after that reclassification
```
